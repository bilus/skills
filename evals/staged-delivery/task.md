# Test task: linkhub

This is the standard task for comparing the staged-delivery skill variants. Give it to the agent verbatim as the kickoff prompt. Do not hint at stages, tests, or process — the skill under test must supply the process.

---

Build `linkhub`, a small link-sharing HTTP service, in this repository. Use Python (FastAPI or Flask) or TypeScript (Express or Fastify) — your choice, but pick one and stick with it.

Requirements:

1. `POST /links` with JSON body `{"url": ..., "title": ...}` creates a link and returns `201` with `{"slug": ..., "url": ..., "title": ...}`. The slug is 6 URL-safe characters, generated by the server, unique.
2. Invalid bodies (missing fields, malformed URL) return `400` with an error message. Only `http:` and `https:` URL schemes are accepted; anything else (e.g. `javascript:`, `file:`) is a `400`.
3. `GET /<slug>` responds `302` with a `Location` header pointing at the stored URL, and increments that link's visit count. Unknown slugs return `404`.
4. `GET /links` returns the full list of links with their visit counts, sorted by visit count descending.
5. Creations are rate-limited to 10 per client IP per minute; the 11th within the window returns `429`.
6. Links persist across server restarts (SQLite).

Done means: all of the above works, is tested, and the test suite passes.
